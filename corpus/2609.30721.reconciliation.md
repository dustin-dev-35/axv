## The two AXV-6 and AXV-8 memos are complementary, not competing

`corpus/2609.30721.md` swept Type-I error across five dependence levels using a generator AXV
wrote, because at the time the paper's `simulation.py` had not been obtained. Its own leaderboard
records carry the warning verbatim: *"Not a replication of the paper's simulation. The paper does
not release its DGP parameters; the estimator is the paper's and the data-generating process is
AXV's, swept over dependence strength rather than tuned to match the paper's numbers."*

`axv-2609.30721-calibration-01` then read `simulation.py` out of the authors' released artifact
and found where the dependence actually comes from: a shared window term built on raw shocks,
with `sigma_subject=0.45`, `sigma_session=0.25`, `sigma_window=0.75`, `sigma_model=0.60`,
`rho_pair=0.50` and `raw_ar_phi=0.0`. **The dependence is not AR(1) in rho at all.** That is
why the AXV-6 sweep moved the number the way it did, and it is why the two memos agree: the
sensitivity map was real, and the calibration run found the setting the map was missing.

`G_info` and the CI-inflation figures were re-derived in the calibration run with **max absolute
error 0.0** against the paper's own `information_growth.csv`, which is the strongest form of the
reproduction and is independent of the DGP question.

## A correction that is on the record and is not buried

An earlier AXV-8 run, `20260928T210000Z-a2609-30721-audit`, reported `verdict:
partially-confirmed` and asserted that the paper's 16.9% and 7.2% figures **did not reproduce**.
**That assertion is withdrawn.** It ran against a substitute generator of AXV's own design
because the authors' released code was not available to it at the time, so the gap it measured
was a property of its own generator and not a defect in the paper. The retraction is carried in
`experiments/leaderboard.jsonl` as a **new record with `supersedes` pointing at the original**,
never as an edit, and the surviving results from that run are restated in the addendum under its
own confidence label.

## What is still open, and it is not a content question

1. **Notion has never received this paper.** Notion Corpus is the canonical home for a reading
   memo and the connection reports `state: ready` while exposing no callable tool to this agent
   run. Until that is fixed, all four files above are GitHub copies with no canonical behind
   them, and `mirror_health` would show a `pending` row that nothing can currently clear.
   **Re-checked 2026-09-28 in the run that filed `corpus/2609.30721.axv-8-generators.md`: still
   blocked, and the cause is unchanged and is not a token that expired.**
   `PAPERCLIP_RUNTIME_TOOLS_AVAILABLE` is `connections_search,connection_request` — two
   coordination tools, and **no** Notion, Supabase, PostHog or Runpod tool is present in the run
   at all. `PAPERCLIP_RUNTIME_TOOLS_URL` is empty, so the runtime-tools endpoint is not even
   addressable, and `GET /api/tool-gateway/tools` with the run JWT returns **401**. The same
   three facts are recorded in `experiments/AXV-6-mirror-status.md` and on
   [AXV-2](/AXV/issues/AXV-2). So: the Notion Corpus page, the Supabase `corpus_index` and
   `experiment_runs` rows, and the `axv_memo_published` and `axv_experiment_recorded` PostHog
   events **do not exist for any of the four memos**, and no agent can create them until the
   control plane exposes the service tools. GitHub is the only mirror in this file, and it is
   complete: memo, run directory, and 90 leaderboard rows at commit `92f7167`.
2. **Supabase has no memo index row and no `experiment_runs` rows**, for the same reason, and the
   triage ledger row that started this is still **provisional** — the claim string came from the
   issue body, not from a `triage_ledger` record.
3. **The canonical path still holds the AXV-6 memo.** It is not wrong, and it is not edited here:
   `corpus/<arxiv-id>.md` is a GitHub *mirror*, the canonical is Notion, and Notion is
   unwritable, so superseding the mirror from here would be exactly the mirror edit the storage
   contract forbids. When the Notion write is unblocked, the correct order is: write the merged
   memo to Notion first, then propagate that file to `corpus/2609.30721.md` in one commit, and
   retire this note.
4. **Two agents were assigned one paper with no lock.** Three runs exist because concurrent
   assignment was possible. The reconciliation above is a content decision made inside Lens; the
   *lock* is a control-plane gap and it is not Lens's to close.
